# CW trainer source audit

September 30, 2026. This report compares the original n1rwj.com trainer and its
related public tools with the current CW Academy Companion source. The Companion
has usable practice tools, but it still does not reproduce the original workflow
for doing an assignment, returning to interrupted work, recording the evidence,
and preparing an advisor report. Matching tool names obscures substantial gaps.

The highest priorities are protecting unfinished practice, tracking actual audio
passes, preserving playback continuity, completing the advisor report workflow,
and making repeated assigned Runner practice practical. Sending capture is an
entire missing subsystem; the scales reader itself is now present.

## Assigned audio and focused recall

1. **P1 Partial: actual required passes.** The original merges listened coverage
   and counts a full pass only when substantially all the recording was heard.
   It distinguishes previous saved passes, this block's passes and remaining
   requirements. The Companion displays the prescribed pass count but tracks
   only seconds; seeking near the end is neither a complete pass nor usable
   coverage evidence. Add per-recording coverage, saved pass counts and visible
   remaining passes while retaining independent learner completion.
2. **P1 Missing: assigned replay policy.** The original distinguishes course
   recording replay from daily word replay: course replay stops when block passes
   are satisfied, while optional daily words may loop beyond their ten-minute
   goal. The Companion's assigned recording has no comparable
   replay controls or pass-based stopping policy. Generic word-list Repeat is
   a different feature. Add visible course replay preferences and a deliberate
   stop/repeat choice after the required listening.
3. **P1 Partial: remembering a recording choice.** Native speed variants and the
   global Assigned/Next default work. The original also remembers an override
   for the particular task and exposes selection in task context. The Companion
   reopens using the global preference, losing an individual assignment's
   chosen variant. Retain per-task choices, including revisits and recovery.
4. **P1 Missing: difficult timestamps and short replay.** The original offers
   Replay 8 sec, Mark difficult here and saved timestamp buttons, scoped to the
   selected recording. The Companion offers the native scrubber only. Add a
   one-action rewind and named timestamps that survive revisiting the exercise;
   changing native-speed files must not apply another file's marks.
5. **P1 Partial: recall interruption and correction.** A separate recall timer
   exists, contributes to total time and pauses when hidden. The original also
   rejects delayed timer ticks of four seconds or more and allows correction
   of recall time within the finished total. The Companion clock accumulates
   continuous manual elapsed time and the save form cannot correct the recall
   measurement separately. Add the interruption boundary and a validated recall
   correction without double-counting playback. Ordinary sending/manual timers
   also lack the original hidden/delayed-tick guard; their intended off-page
   timing policy should be explicit.
6. **P2 Missing: exercise-specific listening guidance.** The original provides
   distinct head-copy goals and scratchpad prompts for words, phrases, affixes,
   QSOs, POTA, CWT and stories. The Companion shows assignment notes plus generic
   instructions and a generic scratchpad prompt. Restore concise family-specific
   guidance, including when retaining meaning or fragments is the goal instead
   of producing a full transcript.

## Continuity and fidelity of saved practice

7. **P1 Partial: recovery after reload or a crash.** The original saves the active
   assignment, source, exact generated draft, elapsed time, audio position,
   coverage, scratchpad and acknowledged Runner progress, then restores paused.
   The Companion preserves copy drafts and scratchpads, but other active clocks,
   audio positions, custom lists and generated scripts remain in memory. A
   before-unload warning does not recover work. Persist a scoped complete draft,
   checkpoint it, restore paused and prevent two tabs from independently crediting
   the same draft. The original also permits visiting Today, Week or Report
   without ending the active block; Companion listening navigation saves and
   resets it. Add a way to inspect the plan and return to the same block.
8. **P1 Partial: saving without a reliable connection.** Finished copy and
   navigation-saved listening use a durable stable-ID queue. Ordinary manual
   review/save and Runner review go through the API-dependent SessionModal;
   failed work has no equivalent durable active recovery. Extend the finished
   record queue to these flows and retain the exact retry body and identity.
   Plan/status/settings edits likewise depend on direct network requests rather
   than the original broad local-first synchronization. The original uses
   timestamps to reject stale preference writes; current settings have no
   comparable version boundary. Do not describe all autosaving or offline
   queues as absent.
9. **P1 Partial: recording what was actually practiced.** Original generated
   listening records each distinct played setup, and QSO practice records used
   selections, station calls and settings. Exact text/script recovery is in the
   original active draft; its finished history stores configuration summaries,
   rather than full scripts. A Companion listening entry is labeled with the final
   selected list/scenario and character/effective speed. It omits the exact
   generated script/custom list and all earlier played settings. A block that
   contains two speeds can be mislabeled as only the last speed. Save played
   segments or source summaries, independently of settings merely selected.
   Official recordings already retain separate actual URL/WPM/time metadata.
10. **P1 Partial: extra review versus assigned work.** The original marks extra
    practice `review:true` and excludes it from assignment progress. The
    Companion's Review exercise opens the same task and saves the same
    `plannedTaskId`, without a native review flag. Those minutes accumulate in
    the task-linked total. Preserve review as independent useful practice,
    excluding it from required minutes/passes while retaining it in daily time.
11. **P1 Partial: source-specific validation.** The Companion validates native
    copy evidence and derives its measured form fields from the attempt. Other
    metadata is accepted as a generic bounded object. It lacks equivalent
    domain checks for Runner dates/time/points, recording and recall consistency,
    and structured CWT measurements. Add typed validators and result views before
    using those fields as advisor-report evidence. This is a data-integrity gap,
    not a claim that someone can access another account.
12. **P2 Missing: complete device backup and local-only clear.** The original
    device export includes active work, pending records, report drafts and local
    preferences; clearing that device is distinct from deleting synced history.
    Companion account export returns server records and retained import archives,
    omitting active copy drafts, pending local results and scoped scratchpads.
    Add an explicit device export/clear workflow and describe what an account
    backup does and does not contain.

## Generated listening and its controls

13. **P1 Partial: changing speed while listening.** Original words finish the
    current item at its old speed and apply the new speeds to later items.
    Original QSO/story playback preserves the exact word occurrence, including
    repeated words, and playing/paused state when retimed. Companion speed changes
    stop playback and clear the prepared track. Resuming starts at an item's
    beginning, losing the within-transmission position. Restore those two
    appropriate retiming policies; changing volume should also not interrupt
    practice. The original deliberately starts fresh for list/pitch/spacing
    changes, so seamless handling of every setting is not a parity requirement.
14. **P1 Partial: seek and navigation semantics.** Original word jumps and Back
    10 sec preserve playing versus paused state. Companion Previous/Next always
    pause; transcript word buttons always start playing. There is no dedicated
    Back 10 sec control. Make position selection preserve the current state and
    offer an explicit replay action when playback is intended. Existing buttons
    are labeled Play from, so the automatic play is observable behavior rather
    than an unlabeled accessibility bug.
15. **P2 Partial: Shuffle with Repeat.** Original generated repeating word rounds
    prepare a newly shuffled order while preserving VVV as the QSO opening.
    Companion Morse-only Repeat loops the same native recording and therefore
    the same order. Its spoken-answer path does reshuffle. Repeat should create
    a new order in both modes when Shuffle is enabled. Changing Shuffle currently
    resets the round, and changing Repeat stops and clears it. The original
    applies these continuation choices without cutting off the current item.
16. **P1 Partial: custom word lists.** Original custom text lives in the saved
    draft and the built-in list can be edited into custom. Companion custom text
    exists only while ListeningTrainer is mounted; a tool switch or reload loses
    it, and there is no Edit this list path. Persist it by appropriate scope and
    allow starting from a built-in list. Both parsers cap lists at 200 words; this
    is not a missing 500-word capability.
17. **P2 Missing: Stories mode.** The original public listening engine exposes
    three authored stories through the same transcript, speed and transport
    controls as QSOs. The Companion has Words, QSO and free text, with no authored
    story selector. Free text can play a pasted story but does not reproduce the
    tool. Add an actual third listening mode with story selection and recovery.
18. **P1 Partial: spoken answers during background listening.** The original uses
    published spoken clips and composes three Morse repetitions plus the answer
    into a complete native track, with matching prebuilt MP3 paths. Companion
    speechSynthesis needs an installed local English voice and stops when hidden;
    JS callbacks schedule later words. Foreground three-repeat behavior is now
    implemented, but it does not provide the original dependable native-audio
    spoken round. Use a rights-cleared native speech-audio path; retain local
    speech as an explicit fallback if useful. The original also has a matching
    preset MP3 fast path and speech-clip caching; neither exists here. The
    Companion's ability to speak arbitrary valid custom words through a local
    voice is a useful capability beyond the original finite clip vocabulary.
19. **P2 Partial: independent mode preferences and precise controls.** Original
    Words, QSOs and Stories keep separate setups and offer speed presets plus
    numeric controls through 60 WPM, finer pitch and pause entry. Companion uses
    one character/effective speed and tone across listening modes, ranges through
    50 WPM, 25 Hz tone steps and a fixed pause menu. Switching from fast word
    recognition to a QSO inherits the word setup. Preserve both speeds per mode
    and provide precise entry. The original preference writer itself drops QSO/
    story effective speed; that omission should be corrected rather than copied.
20. **P2 Partial: two station pitches at the upper bound.** Original QSOs use
    fixed distinct 450/500 Hz tones for the two speakers. Companion clamps
    `tone + 50` to 1000 Hz, making both speakers 1000 Hz at that setting. Keep a
    distinct pair within bounds so station changes remain audible.

## Sending and Morse Runner

21. **P1 Missing: optional sending input and capture.** The original has adapter
    setup/help, MIDI device selection, an input test and focus-scoped
    keyboard practice; it captures raw key-down/up timing, cautiously decodes the
    result, compares it with a target and supports reset/review. Companion
    SendingScales is a reader and timer. There is no input/device/take state or
    analysis interface. Port this optional subsystem while keeping ordinary key
    practice usable without a connected adapter.
22. **P1 Missing: sending take review and replay.** The original can replay the
    measured keyed timing or generated ideal reference sending, show take details, keep
    or discard takes, retain ten recent recordings locally and optionally attach
    a summary to history. The Companion cannot record or replay a take and has no
    retention controls. Add local takes and summaries; captured replay does not
    itself add practice time. The original has neither microphone capture nor
    an iambic browser paddle keyer, so those are not parity gaps.
23. **P1 Partial: cumulative Runner assignment progress.** Both sites have the
    actual embedded engine, Single Call/WPX settings and individual results. The
    original shows prior saved time plus this run, remaining assigned time and
    derives Runner completion from cumulative seconds. Companion shows the
    current run and has separate manual completion; the runner component lacks
    the saved assignment total/remaining display. Show cumulative progress and
    decide explicitly whether to adopt the original completion rule.
24. **P1 Missing: Save and start next run.** Original review offers Save & start
    new run and retains useful settings, with each run's identity intact.
    Companion review is a general log modal; a confirmed manual save returns to
    Today, requiring the assignment to be reopened. Add one action that saves
    that run and starts another without losing the assignment or combining scores.
25. **P1 Partial: Runner result date and recovery.** Companion run metadata
    retains engine start/end times but review omits the entry date/identity;
    SessionModal defaults to the review date. A run across midnight can appear
    under the wrong practice day. The generic WPM field also always uses starting
    WPM even after speed changes; the actual timeline remains in metadata and
    notes. Label the start explicitly or avoid implying a single speed for a
    mixed-speed run. Its acknowledged partial result is also only
    in memory until saved. Use the measured run start in the learner's timezone,
    a stable run-derived save identity and a durable acknowledged result. Recover
    the result, rather than pretending to resume the live contest engine.

## Doing the daily curriculum

26. **P1 Partial: resume and next eligible exercise.** Original Today offers
    Resume current block first; otherwise it favors today’s work over earlier
    work, prioritizing started tasks within an assignment date, and offers
    Start next block.
    Companion offers a list of individual launch buttons, but no recoverable
    current block or context-aware next action after a save. Add resume/next
    behavior using today's dated work and the existing assignment ordering.
27. **P2 Missing: deliberate optional review.** Original suggestions rotate
    previously introduced exercises and retain current-course Runner/ICR review
    settings without advancing future assignments or crediting the source task.
    Companion can manually reopen any task or use public practice, but has no
    equivalent familiar-review suggestion. Add bounded suggestions with the
    review separation described above.
28. **P1 Missing: optional daily word-listening suggestion.** Original Today
    displays a separate optional ten-minute daily listening activity and its own

## Additional timing and device ergonomics

45. **P1 Partial: pending uploads can repopulate reset or replaced history.**
    This is a source-based lifecycle inference. Account RESET and replacement
    import change server records and reload the account, but neither clears nor
    suspends the account's independent local pending-save queue or in-flight
    saves. The app retries that queue on mount, reconnect and every 30 seconds.
    A previously pending listening/copy entry can therefore reappear after reset
    or replacement. Account backup also excludes these pending records. Define
    one reset/replacement operation boundary that reconciles pending and in-flight
    work, with a recoverable export of device work. No destructive operation was
    run to establish this finding.
46. **P1 Different: spoken recognition credits less than the native round.**
    Original three-repeat rounds put Morse, intentional repeat gaps, speech and
    post-answer gaps in the same native recording, so all its played movement
    counts. Companion ends each short Morse recording, schedules gaps with JS
    and speaks through speechSynthesis. Automatic credit counts the Morse
    segments, excluding spoken answers and those intentional pauses. Compact
    Morse-only rounds embed their spacing and credit it. Reconcile the credited
    practice policy between recognition modes; a separately started manual timer
    is not an ergonomic substitute for automatic measurement.
47. **P2 Different: short or notes-only sessions require extra steps.** Original
    generated quick saves accept at least one second and the finish workflow can
    save an attempt containing notes with no time. Companion navigation drops
    elapsed time below 30 seconds, while retaining local notes. Review/save or
    explicit completion can retain at least one second, but Review/save is
    disabled at zero and notes-only completion creates no account practice entry.
    The server permits zero-minute manual records. This is a disclosed navigation
    policy and a notes-save workflow gap, rather than a server inability to retain
    notes. Provide an explicit save-notes action and decide whether short
    assignment practice should be retained automatically.
48. **P2 Partial: sending reader comfort and place are not remembered.** Original
    sending/material reader offers a continuous 18–48 px size control and stores
    task/material reading size and scroll position. Companion offers Standard/
    Large only, in component state; leaving/reopening resets size, section and
    reading position. Add a useful size range and remembered place per section.
    The Companion reader deliberately uses native patterns and original guidance,
    rather than copying the entire private/source text; the linked PDF and future
    private material reader supply exact instructed text where needed. That
    content substitution should remain explicit.

## Verification and practical limits

A fresh isolated guest browser session exercised this checkout at desktop
1440 by 1000 and mobile 390 by 844. The sampled mobile studio fit its viewport
without horizontal overflow. Real native generated audio played. Changing
character speed while playing left audio paused with its prepared position reset;
the coarse word label remained until playback was prepared again. Reloading a
synthetic session with 12 seconds of practice restored its scratchpad, while
elapsed time reset to 00:00 and the current word reset to the beginning.

These were frontend checks against Vite. No private backend was attached to that
browser session; its API error is a local setup condition, not a reported
production defect. Private backend conclusions come from routes, SQL, validators
and existing integration tests. The five focused suites for practice clock,
studio session, preferences, listening content and plan passed: 40 tests total.
The audit did not run the entire browser suite or claim full-device verification.
Physical iPhone lock-screen playback, artwork and speech behavior remain
unverified; browser emulation and Media Session source cannot prove them.

## Recommended implementation order

1. Protect unfinished work and preserve evidence: complete drafts for assigned
   audio/generated listening/Runner, stable retries for manual results, exact
   played settings, result dates and typed validation. Verify reload, uncertain
   save and export/import without duplication or reassignment.

   speed choices, replay/marks, recall correction and family-specific guidance.
   Keep minutes, passes and explicit completion separate.

   progress and Save & next run, optional daily listening and live CWT eligibility.

   windows, editable drafts, evidence suggestions, learned words, exact handoff
   and confirmed submitted snapshots.

   public tools. Sending text practice remains usable while capture is built.

history, recovery and relevant reporting. A new button or a retained metadata
object alone does not close a finding.
