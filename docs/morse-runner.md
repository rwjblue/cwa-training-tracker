# Embedded Web Morse Runner

The simulator uses [Web Morse Runner by DJ1TF](https://github.com/fritzsche/WebMorseRunner),
pinned to revision [`847e9089ef379a065d1cf6807c09f0724bbe072e`](https://github.com/fritzsche/WebMorseRunner/tree/847e9089ef379a065d1cf6807c09f0724bbe072e).
Its [Unlicense](../public/vendor/web-morse-runner/LICENSE) is retained. The
vendor directory contains no personal training data or CWops course content.

`public/vendor/web-morse-runner/upstream/` is the byte-identical reviewed
source. `runtime/` and `index.html` are generated from it. Our bootstrap,
versioned message adapter, and responsive theme live in `integration/`.
Generated patches fix module-relative AudioWorklet and data paths, isolate
storage keys, add attribution and accessible labels, and load our bootstrap.
Keep generated assets out of automatic formatting; their hashes are checked.

The upstream call registry and example datasets are excluded because their
provenance was not established. The local list contains 512 deterministic
synthetic practice strings generated by our update script. Any match to a
real callsign is incidental. Simulator contacts are not on-air contacts.

## Run boundary

The same-origin frame is `/vendor/web-morse-runner/index.html`. Its protocol
is defined in `src/shared/runner.ts` and mirrored by `integration/bridge.js`.
An explicit `morse-runner` exercise recipe supplies mode, WPM, duration,
activity, and band conditions. Titles and private notes do not select the
engine, and no profile, assignment text, or contact log crosses the bridge.
The frame has a dedicated CSP in `public/_headers`. Its production
`connect-src` names `https://cwa.n1rwj.com/vendor/web-morse-runner/`; a fork
or alternate deployment domain must update that source as well. Local
development permits the matching localhost asset path.

The parent sends `configure` once per frame and may send `stop`. Playback
requires the learner's Run click inside the frame. There is no parent start
command. The adapter emits `ready`, `started`, `progress`, `speed`, and one
terminal `results` or `error` event, with a run ID, sequence number, and
audio-engine elapsed seconds. The parent must verify both the frame window
and same origin before parsing an event. Both sides reject extra fields and
invalid numeric bounds.

Only accepted audio-engine time earns practice credit. Wall-clock receipt
timestamps are descriptive, and a run can finish without completing its
assignment. Actual settings are captured on Run; duration and mode then
stay fixed, while speed changes remain available. The reducer rejects
reordered, duplicated, wrong-run, regressing, or post-terminal events.
Starting again needs a fresh frame and run ID. A hidden page or interrupted
audio context ends the current run instead of accumulating idle time.

Results contain only QSO count, verified points and score, and NR/NIL error
counts. Speed metadata retains the starting speed and at most 255 recent
changes, with a separate total count. Automatic notes are also bounded and
identify omitted earlier changes. Imported recipes accept the same exact
settings schema: Single Call or WPX, 10–60 WPM, 60–6000 seconds, activity
1–9, and explicit boolean conditions.

## Verification and updates

Run `rtk proxy mise run verify-runner` to reproduce the generated bundle
offline and compare every source and generated asset. The focused runner
unit tests perform the same check once and cover the protocol/lifecycle.
Browser coverage must exercise the real frame and AudioWorklet; pure tests
do not establish that audio works on a particular device.

To investigate an update, run
`rtk proxy mise exec -- node scripts/web-morse-runner/update.mjs --inspect FULL_SHA`.
Review the upstream change, license, runtime imports, patch anchors, and
bridge assumptions before updating `scripts/web-morse-runner/approved.json`
with that revision and its source hashes. Then run
`rtk proxy mise exec -- node scripts/web-morse-runner/update.mjs FULL_SHA`,
update `RUNNER_REVISION`, verify the bundle, and test a real run. The updater
rejects unapproved revisions, unknown generated files, changed source
hashes, and incompatible patch anchors. It preserves `integration/`.

For a local generated patch, change `makeBundle` in the updater, regenerate
from the verified local `upstream/` files, and refresh `UPSTREAM.json`.
Never directly edit `runtime/` or the generated wrapper: verification would
correctly reject the result. Keep adapter changes in `integration/` and
mirror any protocol changes in the typed parent bridge.
